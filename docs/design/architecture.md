# TekesAppHost 框架设计

日期：2026-10-21

状态：设计基线；尚无实现。接口名称为职责示意，未冻结 API、WIT 或 IPC 格式。

## 1. 目标与范围

维护一套共享 App Host 源码，按构建 profile 预定模块组合、平台能力和发行资源，构建并打包成不同 target apps。Host 的 toolbar、Panel 容器和 splitter 均使用 native TekesUI 组件，由 Host 组合并管理其布局状态；每个 Panel 拥有独立模块进程，该进程加载预定的 content WASM，并输出内容画面、事件和请求。

这是一套公共框架与共享启动入口，不是生成多份 App 源码的代码模板。消费产品通过装配配置及必要的 host adapter 接入，不复制 Host 的状态机和 View。

本规范只讨论通用 Host、模块边界、三列布局、进程管理、渲染合成和输入输出契约；不列举具体业务 WASM，不定义业务 Kit 的内部结构或业务模型。

首版不提供用户安装插件、运行时发现任意模块、产品切换、模块热替换或热卸载。构建时选定模块，启动时加载随 App 打包的 WASM；固定装配不意味着将 WASM 静态链接为 Host 原生代码。崩溃后重新启动同一预定模块不属于动态插件替换。

## 2. 分层与所有权

| 层 | 负责 | 边界 |
|---|---|---|
| TekesUI | 通用组件、布局、文本、输入、焦点、无障碍、动画与绘制 | 不依赖 TekesAppHost、业务类型或模块目录 |
| TekesAppHost | 窗口、三列容器、原生 toolbar、布局恢复、模块进程监管、输入与消息路由、内容合成 | 不实现业务 View 或复制业务状态机 |
| 模块运行进程 | WASM runtime、平台/GPU 桥接、内容帧输出、模块协议适配 | 每个 Panel 独立运行；不直接控制其他 Panel 或整个窗口 |
| content WASM | 按用途组织的业务界面与逻辑、toolbar 注册、事件/请求输出 | 公共接口是模块级接口，不是逐个导出底层组件 |
| target app / 外部能力提供方 | 固定装配、产品资源、业务权威状态、业务协调与能力适配 | 通过通用契约注入；Host 不包含产品条件分支 |

Kit 是源码和能力的复用边界，WASM 是按用途组织的交付单元，二者不要求一一对应。多个 WASM 可以复用同一 Kit 源码；一个模块内部也可组合多个组件。本规范不要求模块内部再为每个组件启动进程。

可复用 Agent 界面及其呈现状态遵守 TekesClientKit 的单一所有权约定。未来使用其他模块组织名称或增加 WASM 交付形式，不能据此在 Host 中复制 Agent 的 run/transcript/composer、设置、任务或线程列表实现。需要改变既有所有权时，先另行明确迁移方案。本设计不修改 Kernel。

## 3. 三列布局

```text
App window / workspace（native TekesUI）
┌────────────────┬────────────────┬────────────────┐
│ left           │ middle         │ right          │
│ ┌────────────┐ │ ┌────────────┐ │ ┌────────────┐ │
│ │ toolbar    │ │ │ toolbar    │ │ │ toolbar    │ │
│ ├────────────┤ │ ├────────────┤ │ ├────────────┤ │
│ │ content    │ │ │ content    │ │ │ content    │ │
│ │ (WASM)     │ │ │ (WASM)     │ │ │ (WASM)     │ │
│ └────────────┘ │ └────────────┘ │ └────────────┘ │
└────────────────┴────────────────┴────────────────┘
```

`left / middle / right` 是物理槽位，不是导航、编辑器或检查器等固定业务角色。Panel 是有稳定身份的整体，包含 toolbar、content 和模块进程绑定；列指 Panel 当前占据的槽位。

- 三个 Panel 可以交换位置，整列 toolbar 与 content 一起移动；不销毁 WASM、不重启进程、不迁移业务状态。
- 每个 Panel 可以独立调整宽度、隐藏和重新打开；middle 没有必须可见的特殊规则。
- 隐藏不关闭会话或卸载模块，默认保留进程及模块状态，暂停不必要的内容帧生产；业务任务是否继续由业务所有者决定。
- 三列全部隐藏后，仍通过窗口菜单或快捷键恢复，入口不能仅存在于列内 toolbar。
- 记录 Panel ID、槽位顺序、显隐意图、有效宽度及可恢复的焦点引用。窄窗口的临时折叠不覆盖用户显隐意图。
- Host 使用 TekesUI 的 Panel、toolbar 和 splitter 组件管理分列、分隔线及 toolbar 与 content 的几何关系；向模块传入扣除 toolbar 后的 content 视口。
- 多窗口中，即使引用相同 WASM，每个 Panel 实例仍有独立进程和输入/呈现状态，不共享一个可变 UI 单例。

## 4. content 注册本列 toolbar

每列 toolbar 的内容由该列 content WASM 注册。Host 负责原生 TekesUI 容器和控件呈现，模块负责命令语义、描述及业务状态。

```text
content WASM → 注册 toolbar 描述 → 模块进程 / IPC → Host 原生 toolbar
content WASM ← toolbar action ← 模块进程 / IPC ← 用户操作
content WASM → 新状态 / 描述更新 → Host 更新同一 toolbar
```

职责级契约包括：

| 方向 | 内容 |
|---|---|
| 模块 → Host | 注册/更新 toolbar 项、稳定 item/command ID、顺序与分组、标题、图标引用、提示、enable/checked 等投影 |
| Host → 模块 | action、来源 item、Panel/View 身份、上下文代次、交互参数 |
| Host → 模块 | toolbar 可用空间或呈现条件；按需协商支持的控件能力 |
| 模块 → Host | 请求完成/失败、业务状态更新及必要的后续操作意图 |

toolbar 描述是原生控件的贡献数据，不传递原生 Rust View 对象或执行闭包。首版支持的控件集合、菜单/溢出呈现和增量更新格式在接口设计时明确，不预设任意原生自定义 View 已能跨边界传输。

约束：

1. 注册绑定 Panel、View、模块实例代次；模块不能改写其他列的 toolbar。
2. 一批注册先校验 ID、命令引用和可支持能力，再原子发布；失败显示诊断，不留下半个 toolbar。
3. enable/checked 等业务状态由模块或其外部业务权威源提供，Host 只消费投影。Host 自身布局命令由 Host 的唯一布局状态派生。
4. 操作返回模块后重新校验上下文和执行条件；按钮禁用不代替权限校验。
5. 模块断连时禁用该实例的业务操作；Host 保留列外恢复入口和必要的故障提示。
6. 重启清理旧注册，新实例握手并注册完成后才发布新 toolbar；旧代次消息不能覆盖新状态。
7. 隐藏或移动 Panel 不注销 toolbar；关闭 View 或结束对应实例时按生命周期清理注册。

## 5. 每个 Panel 的独立模块进程

```text
App Host（native TekesUI）
  ├── Panel A：toolbar + content 合成区
  │       ↕ IPC / 共享 GPU 资源
  │   模块进程 A：runtime + 预定 WASM + GPU/平台桥接
  ├── Panel B：toolbar + content 合成区
  │       ↕ IPC / 共享 GPU 资源
  │   模块进程 B：runtime + 预定 WASM + GPU/平台桥接
  └── Panel C：toolbar + content 合成区
          ↕ IPC / 共享 GPU 资源
      模块进程 C：runtime + 预定 WASM + GPU/平台桥接
```

Host 内的进程监管器创建、握手、监控和回收进程。可共用一个模块运行器可执行文件，由启动配置选择 WASM；独立进程不要求每个模块有一份不同的原生运行器源码。

建议生命周期：`configured → starting → handshaking → ready → stopping → stopped`；失败进入 `failed`。ready 仅表示接口就绪，首个可显示帧和业务数据就绪分别记录。握手核对协议版本、模块身份、能力、渲染后端和资源格式。

退出、异常、启动失败或无响应时，只将对应 Panel 标为不可用，其他 Panel 和窗口外壳继续运行。Host 不在 UI 线程同步等待模块。超时不能直接等价于业务请求失败；可能有外部副作用的请求需查询权威结果，不能自动重放。

重启时生成新的模块实例代次，撤销旧输入路由、toolbar 注册、挂起请求和 GPU 资源引用。是否支持恢复草稿/任务由模块及外部服务声明；进程隔离不保证进程内状态在崩溃后保留。重启策略设置退避与次数限制，不形成无限重启循环。

进程隔离降低局部故障影响，但不承诺抵御共享 GPU 设备丢失或平台服务故障；这些故障需要统一诊断与恢复路径。

## 6. 模块级 WASM 契约与进程通信

WASM 模块是运行器加载的产物；WASM/Component Model 接口不是进程本身，也不是 IPC 协议。WIT 可用于表达模块级类型与接口，运行器将对应调用及资源句柄映射到 Host 的 IPC 和平台能力。具体标准版本及 runtime 选择待验证后固定。

| 契约组 | 通用职责 |
|---|---|
| 描述与协商 | 模块/协议版本、可创建 View、能力需求和支持的输出方式 |
| View 生命周期 | 创建、配置、挂载、可见性、尺寸、关闭准备、释放 |
| toolbar | 由 content 注册/更新本列控件及命令，接收 action |
| 输入 | 指针、键盘、焦点、组字、拖放、剪贴板协作 |
| 业务 input/output | 上下文投影、事件、请求、结果、错误、取消与订阅 |
| 渲染输出 | 共享画面资源、frame-ready、同步信息、失效/重绘需求与资源回收 |
| 平台语义 | 输入法光标/候选窗定位、无障碍树、光标形状等 |
| 关闭与恢复 | 保存/关闭准备、结果、检查点及可恢复能力声明 |

所有跨边界值都使用明确的序列化数据或受控资源句柄，不传递原生 Rust 指针、闭包或进程内对象。高层模块接口不要求公开 TekesUI 的每个组件；内部使用 TekesUI 所需的 GPU/平台导入是运行器基础设施契约，与业务模块对 App 的公共接口分开。

消息信封至少关联协议版本、workspace/Panel/View ID、模块实例代次；请求另有 request ID，上下文和视口更新另有对应 revision。规定消息顺序、背压、取消/超时、断连、资源释放和不支持能力的错误行为。高频输入和属性更新可按语义合并，点击、文本提交等不可随意丢弃。

模块身份来自构建装配及握手，不能仅凭模块自报获得权限。Host 依据 profile 授予最小所需的文件、网络、凭证等能力，资源引用和请求经过实例/作用域校验。

## 7. 渲染与合成

content 在模块运行进程中完成状态更新、布局与内容绘制，Host 接收渲染结果，不在 Host 中重建业务组件树。Host 仍使用 native TekesUI 绘制窗口、三列容器和 toolbar，并完成最终合成。

WASM 不能直接调用宿主进程内的 native Rust 对象。目标架构要求验证 TekesUI 的可移植组件/布局路径及运行器提供的原生 GPU/平台桥接；不能将已有 native TekesUI 打包改名就视为可用 WASM。如何拆分编译及暴露内部渲染能力需要原型确定，但不改变对外的大组件契约。

首选内容输出为共享 GPU surface/texture 及帧同步信息，而非每帧读回 CPU 的像素数组。wgpu 负责适合 GPU 的工作；跨进程纹理导入/导出由平台适配层提供，普通 wgpu Texture 对象不直接跨进程传递。macOS 可验证 Metal/IOSurface 路径；其他平台分别验证，不承诺已有统一零拷贝实现。

资源协议需覆盖：尺寸、逻辑点/像素比例、像素格式、色彩空间、透明度约定、资源与视口代次、帧序号、生产完成信号、消费完成/归还、丢帧与设备丢失。资源重建时在 GPU 使用完成后才释放；Host 不采样仍在写入的纹理，模块不覆盖 Host 尚在使用的缓冲。

Host 按窗口刷新时机合成，模块按内容失效和动画需要生产帧。采用有界缓冲和背压；模块暂未产生新帧时保留上一有效帧，不阻塞其他列。视口改变期间旧帧的临时缩放/占位与输入映射使用一致策略，过期帧不替换新视口结果。

独立进程带来隔离和 CPU 工作并行，不保证 CPU 总负载降低或 GPU 并行收益。减少开销依靠避免像素读回、复用资源、增量更新、合批和隐藏暂停；布局、业务逻辑和提交仍消耗 CPU。60 Hz/120 Hz 的帧间隔约为 16.7/8.3 ms，这些只是测量条件，不是当前实现承诺。

## 8. 输入、焦点与平台能力

窗口系统事件首先到达 Host。Host 根据 Panel 几何与当前内容视口转换坐标，路由到对应模块；内容内部的命中测试、交互状态和业务处理由模块处理。toolbar 是 Host 原生控件，其交互通过注册 action 回到模块。

Host 是窗口级焦点和输入目标的协调者，模块管理内容内部焦点。指针捕获、拖动、Tab 导航、快捷键冲突与 toolbar/content 焦点转移使用显式协议。换位或隐藏时结束或转移必要输入状态，不把旧坐标事件送入新几何。

渲染结果之外必须传递输入法与无障碍语义。Host 连接原生文本输入、候选窗位置、选区查询、剪贴板及无障碍入口；模块提供内容语义、文本范围、光标几何和 action。组字不等同于已提交业务文本，不能在换焦点时随意丢弃。

这些桥接属于首版可用性边界，需要真实窗口验证。仅能显示纹理不能视为可用原生 View 已完成。

## 9. 数据所有权与跨 Panel 协调

Host 维护布局、进程、路由和合成状态。模块/外部业务提供方维护业务数据、草稿、checked/selection、业务任务、文档及历史。Host 可以消费只读投影，不复制可独立修改的业务状态机。

跨 Panel 交互由 target app 声明的业务协调适配器通过通用路由处理，Host 不解析具体业务字段。每项业务状态有一个权威来源；多个模块共享会话时，通过明确的服务/协议共享，而非依赖各自编译进 WASM 的 Kit 单例。

上下文切换使用一致 revision：新上下文未提交前保留一致旧画面或显示等待态，不能用新内容画面配旧上下文命令。toolbar 的 enable/checked、content 操作和异步结果关联同一目标与代次；拒绝晚到事件和陈旧回执。

## 10. 隐藏、关闭、退出与恢复

隐藏 Panel 仅影响呈现，不保存、放弃或关闭业务会话。正常关闭 View、窗口或 App 时，Host 协调模块及外部状态所有者的关闭准备，再释放实例和进程。关闭能够表达允许、取消、等待与失败；等待时禁止重复请求。

涉及未保存内容时，先由业务提供方完成必要的编辑协调，明确选择保存/放弃/取消。保存回执关联会话、请求、目标和保存版本；保存期间有新修改时仍保留 dirty 状态。关闭批准绑定版本、实例代次和受影响引用，执行前复核，变化则重新准备；取消或保存失败不能提前销毁 View 或删除草稿。

多 View/进程引用同一会话时，按业务会话去重协调，不把进程退出等同于会话关闭。UI 输入缓冲、业务草稿、已提交模型、持久化记录是不同状态，需分别声明支持的恢复层级。

布局记录只存 Panel ID、位置、宽度、显隐和有效恢复引用；不包含业务真值或隐式权限。Host 按当前固定 profile 校验记录，缺失或不匹配模块显示诊断/默认布局，不从布局文件加载任意代码。业务恢复由模块/提供方的持久化能力完成；重新打开已保存文件不能冒充未保存状态恢复。

## 11. 构建、固定装配与发行

每个 target app 的 profile 至少预定：

- 产品身份、名称、图标、Bundle ID、平台资源及权限配置。
- 三个 Panel 的稳定 ID、初始槽位、默认宽度/显隐与 content 模块引用。
- WASM 精确版本/摘要、接口版本、模块运行器版本及所需平台适配。
- 所需 Host 能力、允许的数据路由和产品业务协调适配器。

构建流程：选择 profile → 校验装配与版本 → 构建共享 Host/运行器及指定模块 → 固定并打包 WASM 与资源 → 按平台要求签名并产出对应 App。模块可来自预构建的不可变产物；不能在发行时静默跟随变化的开发目录。

启动流程：读取打包配置 → 验证模块身份/兼容性 → 创建三列与进程 → 加载各自预定 WASM → 握手 → content 注册本列 toolbar → 获取内容帧 → 进入可交互状态。单列启动失败不阻塞整个窗口，不将失败列视为 ready。

不同 target apps 可以选择不同用途的模块，但复用同一 Host 和运行器实现；不按 Kit 名称强制划分 WASM。开发源覆盖必须显式标明；发行依赖使用已发布的精确 pin，并锁定模块摘要和接口版本。

原型首先验证一个中性 content WASM 在独立进程输出纹理、注册 toolbar、接收输入，再扩展到三列及两个固定 target apps。性能与兼容性未验证前，不把原型画面、离屏测试或接口定义视为生产验收。
